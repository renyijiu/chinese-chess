# 中国象棋 3D 角色概念稿

这组概念稿用于网页 3D 中国象棋的第一轮角色建模。设计只借鉴用户参考图中“古代战争棋雕、圆形棋座、写实 PBR”的整体方向，角色、服饰和装饰均为重新设计。

## 六视图顺序

每张图固定为 3 × 2：

1. 正面
2. 背面
3. 左侧
4. 右侧
5. 顶视
6. 底视

所有视图使用同一静态姿势、同一模型比例、正交镜头和中性棚拍光。底视用于确定统一棋座的底部结构。

## 角色与数量

每方共 16 枚棋子，分为 7 类功能模型：

| 功能 | 红方 | 黑方 | 每方数量 | 造型 |
| --- | --- | --- | ---: | --- |
| 主将 | 帅 | 将 | 1 | 统帅人物 |
| 辅弼 | 仕 | 士 | 2 | 宫廷军师 |
| 象 | 相 | 象 | 2 | 披甲战象 |
| 车 | 俥/车 | 車/车 | 2 | 单马战车 |
| 马 | 傌/马 | 馬/马 | 2 | 重甲骑兵 |
| 炮 | 炮 | 砲/炮 | 2 | 火炮与炮手 |
| 兵卒 | 兵 | 卒 | 5 | 盾矛步兵 |

网页版本建议每一类只维护一套主网格与骨架，红黑双方复用几何，通过材质实例、阵营色和棋子徽记区分。这套方式只需 7 套主模型，不需要制作 14 套重复网格。

## 与角色设计相关的核心规则

- 棋盘为 9 路 × 10 线，棋子落在交叉点上，中间有楚河汉界，两端各有 3 × 3 九宫。
- 帅/将：九宫内每次横向或纵向走一步；双方主将不能在同一路无遮挡相对。
- 仕/士：只能在九宫内沿斜线走一步。
- 相/象：沿斜线走两步，不可过河；中点有棋子时被“塞象眼”。
- 马：走“日”字；先经过的正交相邻点被占用时会“蹩马腿”。
- 车：沿横线或竖线走任意距离，路径不能越子。
- 炮：不吃子时与车相同；吃子时，炮与目标之间必须恰好隔一枚“炮架”。
- 兵/卒：每次向前一步；过河后还可横走一步，不能后退，到底线也不升变。
- 胜负目标是将死对方主将；轮到一方行棋却没有任何合法着法时，该方也负。

## 美术规范

- 红方：深朱砂、鎏金、暖铜、少量象牙色。
- 黑方：炭黑漆、暗墨绿、玄铁、旧青铜与轻微铜锈。
- 统一棋座：两层圆形底座，浅色石质顶面，深色金属包边，底部十字加强结构。
- 角色细节按写实游戏棋雕处理，但控制在网页可实现的复杂度；最终模型应制作 LOD 和纹理压缩版本。
- 图中不直接生成文字。正式模型可在棋座正面增加“帅/将、仕/士”等可替换徽记，以兼顾识别与多语言界面。

## 最终提示词结构

概念稿使用内置图像生成工具制作，公共提示词为：

> 原创古代中国战争棋雕；写实 PBR 游戏资产；统一圆形双层棋座；暖灰棚拍背景；严格 3 × 2 六视图；正、背、左、右、顶、底正交镜头；同一姿势、几何、比例、材质与配件；完整入镜；无文字、无标志、无水印；中等细节并适合网页游戏落地。

角色差异提示词分别限定为统帅、军师、战象、单马战车、重甲骑兵、火炮炮手和盾矛步兵。黑方版本以对应红方图为编辑目标，只替换阵营材质为炭黑、暗墨绿、玄铁和旧青铜，保持网格、构图、镜头和光照不变。

## 红帅 V2 与正式建模管线

红帅后续建模以 `red-marshal-six-view-v2.png` 为唯一当前概念基准；`red-marshal-six-view.png` 和 `red-marshal-sculpt-pipeline-v1.png` 只保留为早期探索记录。概念图用于统一轮廓、尺度、服饰层次和配件位置，不能直接替代三维结构判断。

正式资产按以下顺序制作：

1. 在 Blender 中按 V2 正、背、左、右、顶、底视图建立统一比例参考，先完成可读的大轮廓和双层棋座。
2. 制作高模，重点表现面部、盔甲叠层、布料厚度和金属磨损；高模只用于烘焙，不直接进入网页。
3. 重拓扑得到游戏低模，清理遮挡面，规划关节与可替换附件边线，并为七类角色建立可复用骨骼。
4. 展 UV，烘焙切线空间法线、AO、曲率等贴图，再制作 Base Color、Metallic、Roughness 和 Normal 的 PBR 贴图集。
5. 导出 glTF 2.0 二进制 GLB 到 `public/models/*-web.glb`；应用变换、检查法线/切线、单位、骨骼权重、动画循环和材质色彩空间。
6. 执行 `npm run prepare:model`，用 glTF Transform 合并和去重资源、进行 Meshopt 压缩并限制纹理尺寸，生成 `*-runtime.glb`。当前命令保留 `auto` 纹理策略；正式 PBR 贴图接入并完成画质验收后，再把优化脚本显式固定为 KTX2/Basis（并在构建环境安装 KTX-Software），不能把当前小型调色板贴图当作 KTX2 流程已经验收。
7. 在 R3F/WebGL2 页面中检查轮廓、PBR、动画、LOD、阴影、实例数量、三角面和绘制调用，再在代表性移动设备上验收。

当前 `scripts/generate-marshal.mjs` 和 `red-marshal-web.glb` 是浏览器技术链路的程序化样件。它验证的是尺寸、加载、优化和渲染，不是最终写实角色，也不应被当作 Blender 高模或最终美术基准。
