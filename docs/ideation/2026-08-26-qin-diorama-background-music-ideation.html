Grounding Context

Codebase Context

当前音频基础并不差：全应用共用一个 Web Audio 上下文，具备 master、music、ambient、voice、SFX、UI 六级控制，支持开始手势解锁、后台挂起、空间化棋子音效、设置持久化和故障隔离。真正的短板是音乐内容仍是一段 8 秒五声音阶合成循环，缺少段落、状态衔接、平滑过渡和长局抗疲劳设计。

视觉方向是温暖、哑光、低噪声的 Q 版秦俑博物馆沙盘。声音应对应“陶土、青铜、呼吸、微型仪仗”，避免通用古装大片式的沉重管弦，也不能宣称复原了真实秦代音乐。成熟的互动音乐做法支持分层和分段，但象棋不适合每步都变：音乐应慢速叙事，走子与攻击的即时反馈继续交给 SFX。

Decisive POV

推荐总方向：以“微型帝国仪仗”为音乐身份，以权威棋局状态驱动缓慢变化，以安静间隔保护思考；所有增强都保留当前合成音乐作为失败降级。

I1. Top pick

秦俑微型帝国仪仗

1
Description
创造一个项目自有的“陶土共鸣器”，在空陶敲击、钝青铜与呼吸感之间变化；再以它为中心构成土/气底层、轻弦脉冲、青铜点音和软鼓仪仗四类小型音色。目标是 60–90 秒感知长度或等价的程序化变化，稀疏、温暖、不会抢走棋盘注意力，并始终表述为秦俑幻想风格而非历史复原。
Axis
音乐身份与历史表达
Basis
direct: 美术与角色证据要求声音呼应哑光陶土、老青铜、微型仪仗和安静策略；博物馆资料可支持古代乐器家族作为色彩参考，但不能支撑“真实秦乐”宣称。
Rationale
当前八秒循环只能证明“有音乐”。一个自有音色与小型编曲语言能让声音像秦俑模型一样成为产品识别资产，并可复用于角色、终局和后续场景。
Downsides
需要真正的作曲与长时间试听，不是多加几个振荡器就能完成；若纯合成音色塑造不足，仍可能显得廉价。
身份Confidence · 94%Complexity · Medium

I2. Core behavior

后果时钟音乐导演

2
Description
增加一个只读取已接受棋局快照的音乐导演，把正常对局、将军和终局映射为少量缓慢状态。走子立即由 SFX 响应，音乐只在下一乐句边界承认“后果”；悔棋、重开、继续游戏和切回前台时重新对齐权威状态。任何调度失败都不进入走子等待链。
Axis
棋局状态叙事
Basis
direct: 规则层已经提供 playing/check/ended、终局原因和去重事件；表现监听器明确隔离异常。一次走子可能同时包含吃子、将军和终局，因此应只产生一个有优先级的音乐响应。
Rationale
它让音乐读懂局势，却不会像即时游戏一样每步跳段，也避免音频重新推导规则或在悔棋后停留在错误状态。
Downsides
需要定义滞回、最短驻留与乐句边界；过于保守会让玩家感受不到变化，过于敏感又会产生抖动。
自适应Confidence · 95%Complexity · Medium

I3. Attention first

安静对局编曲模式

3
Description
默认音乐不再永久填满空间，而是播放 15–35 秒的微型仪仗乐句，随后让 8–25 秒的环境声或安静进入。提供 Standard、Focus、Low Stimulation 三种可持久化编曲；低刺激模式去掉紧张层、频繁角色喊话和重复走子点音，只保留简短将军/结果提示与既有文字状态。
Axis
混音、疲劳与可访问性
Basis
direct: 当前每步已有多段空间音效，角色语音在吃子或每三步可能触发，再叠加连续循环会形成注意力负担；独立总线、设置持久化和文字提示已为独立的音频舒适模式提供基础。
Rationale
象棋的核心体验是思考。让安静成为编曲的一部分，比单纯把音乐滑杆调低更能建立舒适且有记忆点的节奏。
Downsides
间歇长度需要通过完整对局试听调校；部分玩家可能把长安静误解为音频故障，需要用环境底色和设置文案建立预期。
舒适度Confidence · 92%Complexity · Medium

I4. Runtime foundation

可控分轨与平滑过渡

4
Description
把永久匿名循环升级为引擎明确拥有的音乐源：每个底层/分轨可启动、淡入、淡出、停止和回收。音量、静音、状态变化、前后台恢复与合成/素材降级统一使用短增益坡度和乐句安全切换；某一层失败时继续播放基础合成层。
Axis
浏览器运行时与性能
Basis
direct: 当前已有单一上下文和增益节点，接口甚至暴露了 linearRampToValueAtTime，但实际仍是瞬时增益写入，并缺少循环停止、交叉淡化、缝隙处理和状态恢复。
Rationale
这是所有自适应方案的最低可靠平台，而且能先独立改善滑杆、静音与循环接缝体验。
Downsides
需要为持久源建立清晰所有权与测试；乐句对齐比普通淡入淡出更复杂，不能让调度器成为第二个游戏状态机。
运行时Confidence · 96%Complexity · Medium

I5. Mix discipline

声场承载力调度器

5
Description
在现有“每种 cue 最多四个”之外增加全局政策：终局 > 将军 > 吃子 > 角色语音 > 普通走子/UI。设置总声源与解码内存上限，保护关键提示槽位，并在密集攻击时合并低价值声音、打断角色闲聊或短暂压低音乐。
Axis
浏览器运行时与性能
Basis
direct: 当前限制只针对同一个 cue，不同 cue 仍可同时叠加；六条总线存在，却没有跨总线语义优先级、抢占或 ducking。
Rationale
新增背景音乐不能以掩盖将军、命中或终局为代价。全局承载力让后续角色音效增长仍然可控，也为移动端提供明确资源边界。
Downsides
优先级与 ducking 参数错误会让声音被吞或产生明显“抽吸”；需要压力棋局与真机试听，而非只测节点数量。
性能与混音Confidence · 93%Complexity · Medium

I6. Bounded delight

终局礼仪短章

6
Description
将死、认输、困毙、重复和棋与无吃子和棋使用不同但克制的 2–5 秒收束：胜负可以有青铜与鼓的落点，和棋更像仪仗停驻或归于安静。每个终局只触发一次，之后进入安静结果底层，不回到开局循环。
Axis
棋局状态叙事
Basis
direct: 规则状态明确区分五类终局原因，认输也会发出独立事件和终局事件；现有系统已经在表现完成点播放胜负提示。
Rationale
这是一个范围小、感知强的改进，也能先验证新的秦俑音色是否成立，再投入整套动态配乐。
Downsides
过度区分会增加创作量；普通玩家未必理解全部差异，因此变化应服务情绪而不是承担规则教学。
终局Confidence · 88%Complexity · Low

I7. Long-term production

创作音色 + 合成安全网

7
Description
保持当前零下载合成音乐作为可靠底层；开始游戏后再机会式加载一套很小的创作音频胶囊——一条 60–90 秒基础、最多两条同步分轨和少量关键短章，在乐句边界原子切换。所有文件必须有可编辑/无损源、作者与授权、哈希、压缩体积、响度、采样率、解码内存、失败降级和自动/人工试听记录。
Axis
素材、版权与验证
Basis
direct: 当前无第三方素材且故障可安全降级，但音频不在 12 MiB 首屏预算、性能 E2E 或来源锁定中；角色资产流水线已经提供可复用的来源、哈希和优化输出惯例。
Rationale
它避免在“音色品质”和“浏览器可靠性”之间二选一：先有即时合成，再让高质量素材成为不阻塞的增强层。
Downsides
复杂度最高，需要创作、编码、版权、预算和真机解码验证；如果纯合成版本已经达到目标，可能没有足够收益支撑这条生产线。
资产交付Confidence · 86%Complexity · High
